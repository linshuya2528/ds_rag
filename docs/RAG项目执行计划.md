# 计算机网络 RAG 知识问答系统执行计划

## 1. 项目目标和完成定义

本项目的目标是完成一个可本地运行的计算机网络课程知识问答系统，并用实验说明 RAG 和 Reranker 是否能提升问答的正确性、证据一致性和来源可追溯性。

最终交付不只是一个聊天页面，而是以下六项成果：

1. 本地课程知识库：教材、PPT、实验资料和笔记可解析、可索引、可追溯。
2. 三种可切换问答模式：直接大模型、基础 RAG、RAG + Reranker。
3. 可运行的 Streamlit 原型：提问、显示答案、显示来源、查看检索调试信息。
4. 80 至 120 道带参考证据的评测集。
5. 三组模式的对比实验结果、失败案例和分析结论。
6. 可复现代码、环境说明、课程设计报告和演示材料。

### 第一版验收标准

- 执行一次入库命令后，可以生成持久化的 Chroma 向量库。
- 输入一个问题后，系统能够返回答案和至少一条可定位到资料、页码、分块的来源。
- 在同一问题集上可以分别运行三种模式并导出结果。
- 资料不足时，RAG 模式明确说明未检索到足够依据，不伪造引用。
- 从空环境按 README 安装后，可以完成入库、提问和评测。

## 2. 当前基础和近期优先级

当前 notebook 已完成或已验证的内容包括 PDF 文本提取、字符/段落分块、BGE Embedding、Chroma 存储、向量检索、CrossEncoder 重排序以及受证据约束的 Prompt。它已经具备 RAG 实验原型的核心链路。

近期不应优先做复杂界面或微调，而应先解决以下问题：

1. 把依赖运行顺序的 notebook 代码迁移为模块化 Python 程序。
2. 固化 chunk、检索结果和回答的统一数据格式。
3. 打通可重复的入库、提问、模式对比和结果导出流程。
4. 建立评测集与指标，否则无法证明 Reranker 的改进效果。

## 4. 统一数据约定

### 4.1 文档页与分块

```python
Page = {
    "document_id": "sha256 前 16 位",
    "source": "计算机网络.pdf",
    "page": 63,
    "chapter": "5.2 路由选择算法",  # 未识别时为 None
    "text": "该页清洗后的文本"
}

Chunk = {
    "id": "document_id-p063-c004",
    "document_id": "...",
    "source": "计算机网络.pdf",
    "chapter": "5.2 路由选择算法",
    "page_start": 63,
    "page_end": 63,
    "chunk_index": 4,
    "text": "文本块内容",
    "char_count": 486
}
```

`document_id` 用文件内容哈希生成，不用文件名生成。这样同名资料更新后可识别为新版本，也能避免旧向量与新 PDF 混用。

### 4.2 检索和回答

```python
RetrievedChunk = {
    "chunk": Chunk,
    "vector_rank": 2,
    "vector_distance": 0.18,
    "rerank_score": 0.91
}

Answer = {
    "mode": "rag_rerank",
    "question": "...",
    "answer": "...",
    "citations": [
        {"source": "计算机网络.pdf", "page_start": 63, "chunk_id": "..."}
    ],
    "retrieved_chunks": [],
    "latency_ms": 0,
    "validation": {"passed": True, "issues": []}
}
```

所有模块都以这些字段为接口。前端不直接读取 Chroma 的原始结果，模型模块也不自行猜测页码。

## 5. 实施阶段

### 阶段 A：工程化和可重复入库

**目标**：把当前 notebook 的稳定逻辑迁移为可测试的代码，并构建第一份教材索引。

**任务**：

- 整理 `pyproject.toml`，补齐 `pymupdf`、`chromadb`、`sentence-transformers`、`requests` 或 Ollama 客户端、`streamlit` 等实际依赖；统一 Python 版本。
- 建立 `.env.example`，集中配置模型名、Chroma 路径、分块参数、Ollama 地址和集合名。
- 实现 PDF 文本提取，记录文件哈希、页码、文件名和可选章节。
- 实现清洗逻辑：删除空白、合并段内换行、识别高频页眉页脚、保留章节标题。
- 实现“段落优先 + 超长段落字符切分”的分块策略，初始参数设为 `chunk_size=500`、`overlap=80`。
- 将分块预览写入 `data/processed/<document_id>.chunks.jsonl`，便于人工检查。
- 建立 Chroma collection；重复入库时按 `document_id` 判断跳过、更新或删除旧版本。

**命令接口**：

```powershell
rag ingest data/documents/计算机网络.pdf
rag inspect --document 计算机网络.pdf --page 63
```

**验收标准**：

- 输出页数、有效页数、分块数、平均长度和跳过页数。
- 随机抽查 20 个 chunk，页码和来源正确，文本没有大量重复页眉页脚。
- 删除 Chroma 后重新入库，得到相同的 chunk ID 和近似相同的统计结果。

### 阶段 B：三种问答模式

**目标**：实现可比较的三条回答链路。

| 模式 | 流程 | 主要用途 |
|---|---|---|
| `llm_direct` | 问题 -> 本地大模型 | 对照组，观察无外部证据时的表现 |
| `rag` | 问题 -> Top-K 向量检索 -> Prompt -> 大模型 | 基础 RAG 基线 |
| `rag_rerank` | 问题 -> Top-K 候选 -> Reranker -> Top-N 证据 -> Prompt -> 大模型 | 改进方案 |

**任务**：

- 将 Ollama 调用封装为单独客户端，设置超时、重试和模型不可用提示。
- 将三种模式的温度、最大输出长度等生成参数保持一致，保证实验可比较。
- 基础 RAG 首次设定 `candidate_count=10`；Reranker 选择前 `top_k=3` 到 `5` 块作为上下文。
- 在 Prompt 中规定：只能使用参考资料；资料不足时明确拒答；每个结论紧跟来源。
- 输出答案、候选片段、最终片段、分数和耗时，供前端与评测共用。

**命令接口**：

```powershell
rag ask "TCP 为什么需要三次握手？" --mode llm_direct
rag ask "TCP 为什么需要三次握手？" --mode rag
rag ask "TCP 为什么需要三次握手？" --mode rag_rerank --debug
```

**验收标准**：

- 三种模式在相同问题上均能运行，并保留独立结果记录。
- RAG 模式的每条引用都能映射回当前检索结果中的 `chunk_id`。
- Ollama 未启动、索引为空、问题为空时返回可读错误，不出现未处理异常。

### 阶段 C：证据校验和拒答机制

**目标**：把“引用来源”从文本装饰变成可验证的数据。

**任务**：

- 要求生成模型返回 JSON：`answer`、`claims`、`citations`、`insufficient_evidence`。
- 验证 JSON 结构、必填字段和页码类型。
- 验证被引用的 `chunk_id` 属于本次最终上下文。
- 若要求模型输出 evidence 原文，检查 evidence 是否是被引 chunk 的连续子串。
- 校验失败时显示原始回答仅供调试，并把正式结果标为“未通过证据校验”。
- 当 Reranker 最高分低于待定阈值，或检索文本无法覆盖问题时，返回统一的“知识库中未检索到足够依据”。

**验收标准**：

- 人为伪造的页码、chunk ID 和 evidence 都会被识别。
- 不可回答问题不会被包装成带虚假引用的确定性答案。

### 阶段 D：评测集和对比实验

**目标**：用数据证明各模块的实际作用。

**评测集字段**：

```json
{
  "id": "routing-001",
  "question": "分散式与集中式路由选择算法的区别是什么？",
  "category": "路由算法",
  "difficulty": "medium",
  "expected_sources": ["计算机网络.pdf"],
  "expected_pages": [63],
  "reference_points": ["集中式具有完整网络信息", "分散式通过相邻节点迭代交换信息"],
  "answerable": true
}
```

**题目配比建议**：

| 类别 | 目标数量 | 核查重点 |
|---|---:|---|
| 概念定义 | 20 | 定义是否准确、是否引用正确章节 |
| 协议比较 | 20 | 关键差异是否完整 |
| 过程推理 | 20 | 条件、步骤和因果是否正确 |
| 条件/计算题 | 15 至 25 | 公式条件和推导是否正确 |
| 不可回答题 | 10 至 15 | 是否稳定拒答而非编造 |

**评测流程**：

1. 对每题人工标注目标页码或 chunk，以及参考答案要点。
2. 对三种模式使用同一批问题、同一模型和相近生成参数运行。
3. 导出每题检索结果、回答、引用、验证结果和耗时到 CSV/JSONL。
4. 由两名成员分别评判回答要点；有分歧时共同复核并记录最终判定。
5. 汇总指标并挑选典型成功和失败案例。

**指标定义**：

| 指标 | 计算方式 | 用于判断 |
|---|---|---|
| Recall@K | 目标证据是否位于前 K 个候选 | 初检索是否找对资料 |
| MRR | 第一个正确证据排名倒数的平均值 | 正确证据是否排得足够靠前 |
| Rerank Recall@N | 正确证据是否进入重排后前 N | Reranker 是否带来提升 |
| 回答正确率 | 参考要点覆盖且无关键错误的比例 | 生成答案是否可靠 |
| 依据一致性 | 关键结论能否由最终证据支持 | 是否存在幻觉或伪引用 |
| 拒答准确率 | 不可回答题是否正确拒答 | 系统边界是否可靠 |
| 平均响应时间 | 端到端、检索、重排、生成耗时 | 可用性与演示体验 |

**验收标准**：

- 完成至少 80 道问题，且包含至少 10 道不可回答题。
- 可一键批量运行，生成带时间戳的结果文件。
- 报告中分别展示检索指标、回答指标和耗时，不能只报告总正确率。

### 阶段 E：Streamlit 原型和可解释调试

**目标**：提供清晰、适合课程答辩演示的最小界面。

**页面功能**：

1. **问答页**：输入问题、选择模式、显示答案和引用。
2. **来源页**：展示最终使用的 chunk、文件名、章节、页码和原文。
3. **检索调试页**：展示向量检索前 K 候选、距离、重排分数和最终选中状态。
4. **索引管理页**：显示已入库文档、页数、chunk 数、模型和构建时间。
5. **评测页**：运行评测、展示汇总表和三种模式对比图。

**界面原则**：

- 默认只展示答案和来源，调试信息折叠隐藏。
- 明确显示当前模式，避免答辩时混淆三组实验。
- 对“资料不足”“模型离线”“尚未建库”使用不同提示。
- 不在第一版实现用户登录、云部署或聊天历史同步。

**验收标准**：

- 完成一次演示流程不需要进入 notebook 或手动修改源码。
- 可以在页面中直观看到“基础 RAG”和“RAG+Reranker”使用了哪些不同证据。

## 8. 参数实验矩阵

为了控制工作量，先只做小型网格搜索，不同时改动过多因素。

| 实验编号 | 分块方案 | chunk 大小 | overlap | 初检索 K | 重排保留 N | 目的 |
|---|---|---:|---:|---:|---:|---|
| E1 | 固定字符 | 500 | 80 | 10 | - | 基础 RAG 基线 |
| E2 | 段落优先 | 500 | 80 | 10 | - | 判断语义分块效果 |
| E3 | 段落优先 | 500 | 80 | 10 | 3 | 验证 Reranker 改进 |
| E4 | 段落优先 | 700 | 120 | 10 | 3 | 观察上下文长度影响 |

先用检索指标筛掉效果明显较差的组合，再对表现最好的 2 至 3 组运行完整的回答质量评测，避免大模型推理耗时过高。

## 9. 风险与应对

| 风险 | 识别信号 | 应对方案 |
|---|---|---|
| PDF 提取质量差 | 文本很少、公式乱码、页码错乱 | 优先文字版 PDF；将关键章节转 Markdown；扫描件单独 OCR，不阻塞主线 |
| 资料混入重复内容 | 检索结果总是页眉、目录或同一段 | 页眉页脚过滤、chunk 去重、目录/习题标签过滤 |
| 模型速度慢 | 单题超过可接受演示时间 | 控制 Top-K、上下文长度和输出长度；准备较小模型作为演示备选 |
| Reranker 无明显收益 | MRR 或回答正确率不升反降 | 检查候选 K 是否足够；减少噪声块；保留负结果并分析原因 |
| 评测主观 | 两名成员评分不一致 | 预先写参考要点和判定规则；双人独立判定后复核 |
| 时间不足 | 第 4 周仍未完成基础 RAG | 暂停 LoRA、扩展格式和复杂界面；优先完成三组对比实验与复现 |
